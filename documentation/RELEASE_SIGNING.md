# Release signing and verification

## Android APK

| Item | Value |
|---|---|
| Application ID (release) | `io.pcwake.controller` |
| Version | 1.0.0 |
| Signing algorithm | RSA 4096, APK signature scheme (v1/v2 as generated by AGP) |
| Signer certificate SHA-256 | `B9:22:35:D2:E2:F6:89:6E:AC:FC:9C:B6:FC:2E:97:FA:CF:AF:0A:92:EA:FB:87:E3:CB:4A:FF:3D:1E:69:FB:D4` |
| Keystore | **Not in this repository**; held privately by the maintainer |

The public signing certificate is stored at
[`pcwake-release-cert.pem`](pcwake-release-cert.pem). Verify a downloaded APK:

```bash
apksigner verify --print-certs PC-Wake-1.0.0-release.apk
sha256sum PC-Wake-1.0.0-release.apk
```

The SHA-256 of the signer certificate must match the value above. The APK file
SHA-256 is published in the GitHub release notes and
[`TEST_REPORT.md`](TEST_REPORT.md).

The debug APK is signed with a throwaway debug key and is intended only for local
testing. It uses the separate application ID `io.pcwake.controller.debug`, so it
can coexist with the release app.

### Maintaining the key

- Back up the PKCS#12 keystore and its strong password offline in at least two
  secure locations. Losing it prevents updates to the release application ID.
- Never commit the keystore/password or share it. The repository contains only
  the public certificate.
- If the key is rotated, document it and expect users to uninstall/reinstall the
  old release because Android will refuse an update with a different signer.

Build a signed release locally:

```bash
export PCWAKE_KEYSTORE_PATH=/secure/path/pcwake-release.jks
export PCWAKE_KEYSTORE_PASSWORD='…'
export PCWAKE_KEY_ALIAS=pcwake
export PCWAKE_KEY_PASSWORD='…'
cd android-app && ./gradlew :app:assembleRelease
```

## Windows MSI

The v1.0.0 MSI in this repository is **not Authenticode-signed**: no code-signing
certificate was available. Windows SmartScreen may warn. Verify the published
SHA-256 and build from source if you require a trusted local binary.

For a production environment, sign the MSI with an EV/OV code-signing certificate:

```powershell
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 `
  /a artifacts\msi\PcWake.Agent.1.0.0.msi
signtool verify /pa /v artifacts\msi\PcWake.Agent.1.0.0.msi
```

Do not commit code-signing certificates or their private keys. The PowerShell
installer scripts are intentionally readable and audited; run them only from a
trusted checkout.

## Wake Bridge

The bridge has no compiled binary and is deployed from source. Use a real TLS
certificate (Tailscale/Let's Encrypt) or the provided self-signed generator, and
pin the certificate fingerprint during pairing. The test fixture certificate in
`wake-bridge/test/fixtures` is test-only and must never be deployed.
